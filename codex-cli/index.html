    Codex CLI integration

    The Codex integration combines two enforcement surfaces:

    Codex Bash/apply_patch ── PreToolUse ──> central native policy + local/remote audit
Codex SDK tool call    ── MCP gateway ──> GuardedRuntime ──> application handler

    The hook governs host-native commands and patches before Codex executes them. The MCP gateway governs SDK-owned application tools, including typed argument validation, live policy, approvals, credentials, budgets, idempotency and execution. Neither surface accepts identity, credentials, approvals or policy claims from model output.

    Onboard one project

    From the project that Codex will operate on, run the command generated by the enterprise UI or invoke the checked-in installer directly:

    export AAI_SEC_AGENT_TOKEN="<short-lived-enrollment-session>"
python3 /absolute/path/to/aai-sec-sdk/scripts/onboard_codex.py \
  --project-root "$PWD" \
  --sdk-root /absolute/path/to/aai-sec-sdk \
  --enterprise-control-plane-url https://control.example.test \
  --deployment-id deployment-example \
  --agent-id codex-example
unset AAI_SEC_AGENT_TOKEN

    The installer writes one owned block in .codex/config.toml. It configures:

    • the required agentic-security MCP server;
    • a PreToolUse hook matching native and MCP tool calls;
    • non-secret deployment and agent routing metadata;
    • the canonical project policy root used for patch confinement;
    • an absolute Python and SDK hook command.

    Both generated subprocess environments pin PYTHONPATH to the selected checkout's src directory. Direct-checkout onboarding therefore does not depend on a separate global SDK installation and cannot accidentally import a different globally installed SDK.

    The short-lived bearer moves to the user-private SDK host cache and is never written to project TOML. Cache identity includes the canonical project root in addition to the control-plane URL, deployment and agent. Bootstrap exchange, session issuance and every agent request are checked against that same registered root, so a cache copied from another checkout fails closed. Existing TOML outside the marked block is preserved. Invalid TOML, ambiguous ownership, unsafe identifiers, unsafe cache state and configuration symlinks fail closed.

    Codex ignores the complete project .codex layer—including the security MCP and hook—until the project is trusted. After onboarding:

    1. start codex from the project root and approve its project trust prompt;
    2. restart Codex;
    3. run codex mcp get agentic-security --json in another terminal and confirm the server is enabled with stdio transport;
    4. open /hooks in Codex and approve the reviewed AAI Security hook hash.

    If Codex does not offer the project prompt, add the following exact block to the user configuration at ~/.codex/config.toml, then restart Codex. Replace the example path with the canonical absolute project root printed by the installer:

    [projects."/absolute/path/to/project"]
trust_level = "trusted"

    Do not treat a generated .codex/config.toml as successful enrollment until the MCP query and /hooks checks both pass. Project trust is appropriate for a pilot, but it trusts the project's full Codex configuration and is not an immutable enterprise control. The installer therefore explains this decision but never silently edits the user-wide trust store.

    What the native hook enforces

    examples/codex_cli_hook.py fetches the authenticated agent's effective group policy for every process invocation. It then applies ordered rules:

    1. destructive command patterns deny;
    2. approval-required command patterns deny the native call and direct it to the governed MCP workflow;
    3. explicitly allowed command patterns allow;
    4. calls under mcp__agentic-security__ reach the gateway, which performs its own live authorization;
    5. apply_patch is allowed only when policy permits editing, the live hook working directory and every declared path remain inside the project root, and no target is SDK security state under .codex, .claude, or .mcp.json;
    6. every other tool denies.

    For an allowed call the process exits successfully without stdout, Codex's documented continue contract. It emits permissionDecision: "deny" only for a denial. A bare permissionDecision: "allow" is deliberately not emitted: Codex reserves that shape for input rewriting and otherwise marks the hook as failed while continuing the call.

    Allowed-command regexes must match the complete command string. Deny and approval regexes search every position, so appending a dangerous shell component to a safe command cannot inherit the safe prefix's authority. Patch confinement validates add, update, delete and move-destination paths. Every command-pattern ingress uses the same bounded validator: no more than 100 patterns per decision class, 256 characters per pattern, and no lookarounds, inline flags, backreferences, quantified groups, wildcard repetition, or ambiguous overlapping repetition, including repeats separated by characters that an earlier repeat could also consume. Command text over 8,192 characters denies before regex matching. These restrictions prevent a stored pattern from exhausting the hook timeout and becoming a fail-open path. Migrate a legacy wildcard pattern to a constrained class around a required delimiter—for example, replace curl\\s+.*\\| with curl[^|]+\\|.

    Before an allow regex is evaluated, the core also requires one shell invocation. Newlines, command substitution, lists, pipelines, redirections and subshell syntax deny and must use governed execution, including control operators quoted inside nested shell or eval arguments. This check is independent of policy regex, so an overly broad administrator pattern cannot authorize a second shell operation. Shell and eval command entry points are also ineligible even when their nested argument contains no punctuation, such as sh -c id; source and . file execution are excluded for the same reason. Detection normalizes path basenames, letter case, and Windows executable suffixes, so forms such as /bin/BASH, bash.exe, and C:\\tools\\SH.EXE cannot bypass the boundary. Use the governed MCP execution path for those operations. Use [ \\t] for intentional horizontal whitespace; \s includes newline and must not appear in a native allow suffix.

    Both direct CodexCliHook.handle() calls and newline-delimited stdio calls return an explicit denial for missing, wrong-type, or otherwise malformed host fields. A validation exception is never part of the integration contract.

    The central kill-switch projection must be the JSON boolean false; missing, null, string, numeric, or active values deny policy activation. Native patch input is capped at 256 KiB and 256 declared source/move targets before any path resolution. The reference hook also caps local native decision history at 1 MB so its mandatory startup/append chain verification stays bounded beneath the host timeout. At that limit the hook denies until an operator exports and rotates .codex/security-audit.jsonl; it never silently truncates evidence. The audit directory, event file, and lock file are opened without following symlinks and verified as regular files. A symlink substitution fails closed.

    Offline fallback commands are intentionally tiny: exact pwd/ls, optional --short for git status, optional --stat for git diff, and optional --oneline for git log. Arbitrary Git options and pytest/python -m pytest are not native-safe defaults because they can write files or execute project code. Route broader inspection and test execution through governed MCP tools.

    Codex PreToolUse currently supports allow and deny, but not an approval-producing ask. Returning ask causes the hook to fail and Codex to continue the call. The adapter therefore records the policy outcome as approval_required evidence but returns deny to Codex. Consequential actions that need approval must be represented as SDK MCP tools, where approvals are exact-action bound, expiring and single-use.

    Each decision is written to .codex/security-audit.jsonl with command/argument and working-directory digests rather than raw content. For an AWS-enrolled agent, the same decision is synchronously exported as content-minimised codex_native evidence. Commands, patches, paths, arguments, outputs and free-form reasons do not leave the host. If required audit export fails, the native action denies. Audit directory creation, file permissions, or an existing corrupt hash chain can also fail during startup; the example catches that condition and emits a deny-only hook response instead of exiting without a decision. A final initialization boundary also converts unexpected adapter exceptions into an explicit denial; no setup exception is allowed to escape as a missing hook result.

    When required remote audit export fails after a provisional local event, the hook denies and appends a local codex_pre_tool_effective_decision linked by supersedes_event_hash. Incident tooling must treat that compensating event as the host outcome and its replication_status=failed field as a durability alert.

    Enterprise-managed deployment

    Project configuration can be edited by a user with repository access. A broad rollout should distribute the reviewed hook script with device management and define the hook in Codex requirements.toml. Pin [features].hooks = true and, where local extensions must not run, set allow_managed_hooks_only = true. Use absolute managed paths and verify the resulting host configuration on every heartbeat. Codex does not distribute managed hook scripts itself.

    The --ignore-user-config automation flag bypassed this project hook layer in acceptance against Codex CLI 0.146.0-alpha.3.1. Do not permit that flag in an enterprise launcher that relies on project policy. Managed deployments must verify that the organization requirement remains active under every approved launch profile and treat missing native decision evidence as unhealthy. The SDK cannot stop a user who is allowed to start an unmanaged Codex process.

    Device management, OS identity, sandboxing, network policy and credential brokering remain deployment-owned controls. The SDK UI can assign policy and observe enrolled processes, but it cannot make a project-owned file immutable. The native patch hook prevents agent-initiated edits to .codex, .claude, and .mcp.json; this protects against model self-modification but is not a substitute for OS-enforced managed configuration.

    Verification

    Test all of these in a synthetic repository before rollout:

    • an allowed status/test command;
    • an unknown command denied by default;
    • an approval-pattern command denied and visible as approval-required evidence;
    • a destructive command denied before execution;
    • an in-project patch and an escaping multi-file patch;
    • an allowed SDK MCP call and an unknown or policy-denied MCP call;
    • loss of policy, session, audit export and heartbeat;
    • emergency stop and session revocation.

    tests/test_codex_cli.py and tests/test_onboard_codex.py provide the executable reference contract.
